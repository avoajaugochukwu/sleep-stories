## 2026-08-13

- **Whisper align: retry transient blips instead of failing the whole job.**
  Symptom: a job with all 287 images done died at alignment with `whisper poll
  failed (500)`. The poll (`lib/align/index.ts`) threw on the *first* non-OK
  response, so one 5xx from the whisper-transcribe Modal container (cold start /
  restart) killed a run whose images were done. Added `fetchResilient` (4 tries,
  linear backoff, retries network errors + 5xx, passes 4xx straight through) and
  used it for both submit and poll. Retry already didn't regenerate images — the
  worker checkpoints the storyboard into `project_json` and resumes
  (`worker.ts:101`) — this just stops the failure.
- **`railway up` failed with 413 (Payload Too Large) — added `.railwayignore`.**
  The upload hit ~224MB and Cloudflare rejected it. Cause: `public/overlays`
  (146MB) + `public/sound-effects` (33MB) + `docs/` (42MB) were in the upload,
  but the web app never serves the first two — they're baked into the **Modal**
  renderer image at Modal-deploy time (`render-modal/modal_app.py` `add_local_dir`),
  and `docs/` is runtime-irrelevant. New `.railwayignore` drops all three from the
  `railway up` upload only (git + the Modal deploy read the local repo, unaffected).
  Note: `.dockerignore` deliberately keeps overlays/sound-effects for local Docker
  builds; `.railwayignore` is a separate concern (the CLI upload).
- **Image-gen poll now survives a network blip too.** `scene-image.ts` already
  retried each image (3 attempts, exp backoff) and its poll `continue`d on a 5xx,
  but a raw network throw mid-poll aborted the whole attempt and re-submitted.
  Wrapped the poll fetch so a network error `continue`s like a 5xx does.

- **Merged `/renders` into `/jobs` — one channel-grouped screen.** The two
  screens did almost the same thing, and a render's ClickUp/project links died
  the moment ClickUp marked the job complete (the job was hidden, so the
  render-side lookup against *visible* jobs found nothing). Now `GET /api/jobs`
  returns one list: live job rows **plus** every finished render. A render whose
  job was hidden is re-attached via `listAllJobs()` (new, hidden rows included)
  keyed on `renders[0].renderId`, so ClickUp + "Open project" survive the
  render's whole 7-day life. Headless leftovers with no job show under
  "Unassigned". `/renders` now `redirect()`s to `/jobs`; header "Renders" link
  removed. Row gained Watch (browser) / MP4 (download) split, Uploaded checkbox,
  and Delete — all on any row with a render. `/jobs` widened to `max-w-4xl`.
  `RenderHistory` component kept — the `/render` editor step still embeds it.

## 2026-08-11

- **/renders row: Uploaded checkbox, real download, View + ClickUp links.**
  Persistent "uploaded" flag keyed by S3 `renderId` in a new `render_meta` table
  (`lib/jobs/render-meta.ts`); `GET /api/renders` merges it in, `POST /api/renders
  {renderId,uploaded}` toggles it. **Download** is now a presigned GET with
  `Content-Disposition: attachment` (`RenderListing.downloadUrl`) — a plain
  anchor downloads it; the blob-fetch approach silently failed on cross-origin
  CORS. "View" opens the MP4 in a new tab. **ClickUp** link per row when the
  render maps to a still-visible job (via `projectJson.state.renders[0].renderId`
  → task). Button hover changed from `bg-accent` (yellow) to `bg-secondary/50`.
- **Video title wraps to centered lines.** Long titles overflowed at fontsize 96.
  `render-modal/modal_app.py` now `_wrap_title()`s into balanced lines and draws
  each as its own centered `drawtext` (Debian ffmpeg 5.1 has no `text_align`).
  **Needs a Modal redeploy** (`render-modal/`) to take effect.
